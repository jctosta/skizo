Skizo

Skizo is a small language to sketch user interfaces. You write one Element on each line. The skizo command checks the file, shows it as a Preview page and exports it as shadcn React code.

Screen "Orders" subtitle="Track customer orders"actionsButton "New order" icon=plus opens=newTable cols="Order,Customer,Amount" rows=3Dialog "New order" id=newInput "Customer"footerButton "Create"
  • Short source. Each line holds one Element. Skizo has no closing tags and no styles.
  • One way to write each thing. Skizo has 33 Element types. skizo check rejects all other types.
  • All errors in one run. skizo check shows each error with a hint.
  • Code that you keep. The export uses the shadcn components of your project.

Get started

Requirements

  • Node.js 22.12 or later.
  • Git.
  • pnpm (recommended) or npm.

Install

Skizo installs from its Git repository. Each release has a Git tag, for example v0.3.0-alpha.1. Always put the tag in the install command. Then each install gets the same release.

Install with pnpm (recommended):

pnpm add -g github:jctosta/skizo#v0.3.0-alpha.1

Or install with npm:

npm install -g --allow-git=all github:jctosta/skizo#v0.3.0-alpha.1

npm 12 and later blocks Git dependencies by default. The --allow-git=all option allows them for this command only.

Make sure that the install is correct:

skizo --help

The install gives two commands: skizo and its short alias skz.

Pin an exact build

A release tag points to a commit on the release branch. This commit holds only the built CLI. It has no build scripts and no dependencies. Thus the install runs no code from the package.

A tag can move to a different commit. To pin one exact build, use the commit hash instead of the tag.

  1. Get the commit hash of the release: 
    git ls-remote https://github.com/jctosta/skizo "refs/tags/v0.3.0-alpha.1^{}"
  2. Install that commit: 
    pnpm add -g github:jctosta/skizo#<commit-hash>

Upgrade and remove

To upgrade, run the install command again with the new tag. To remove Skizo, run one of these commands:

pnpm remove -g @jctosta/skizonpm uninstall -g @jctosta/skizo

Write your first sketch

  1. Save this text as orders.skz: 
    Screen "Orders" subtitle="Track customer orders"actionsButton "New order" icon=plusCard "Revenue" desc="Last 30 days"Stat "$12,450" hint="+12% vs last month" trend=upTable cols="Order,Customer,Amount" rows=5
  2. Check the file. The command shows all errors in one run, each with a hint. 
    skizo check orders.skz
  3. Make the Preview. The command writes orders.html. Open this file in a browser. 
    skizo preview orders.skz
  4. To see your changes while you edit, serve the Preview. The page reloads each time that you save. 
    skizo preview orders.skz --watch
  5. Export the Screens as React code: 
    skizo export orders.skz --target shadcn --out src/screens

Build from source

To change Skizo, build it from a clone of the repository. The build needs Node.js 22.18 or later.

git clone https://github.com/jctosta/skizocd skizopnpm installpnpm buildnode packages/cli/dist/cli.mjs --help

Use Skizo with agents

Coding agents such as Claude Code, Codex and Cursor write Skizo. You look at the Preview and tell the agent what to change.

The command skizo guide prints the Guide. The Guide holds the full language in about 1,200 tokens. An agent needs no other document.

Add these lines to the instructions for your agent, for example in AGENTS.md or CLAUDE.md:

Before you write UI code, make a sketch in Skizo:1. Run `skizo guide` and read the Guide.2. Write the sketch in <name>.skz.3. Run `skizo check <name>.skz`. Fix all errors. Do this step again until the command shows no errors.4. Run `skizo preview <name>.skz` and give me the HTML file.

skizo check shows each error with its line, its Element type and a hint. Thus the agent can fix all errors in one pass:

$ skizo check orders.skzorders.skz:4  Button  unknown prop "varient" — did you mean variant?orders.skz:7  Badge  unknown flag "secondary" — did you mean variant=secondary?orders.skz:9  Table  row has 3 cells, expected 4 (cols: Order, Customer, Status, Amount)

While the agent works, keep skizo preview --watch open. The page reloads after each save that passes check. You can correct the sketch before somebody writes the real code.

Syntax

Lines and indentation

Write one Element on each line. Indent each level of nesting by two spaces. Do not use tabs. A child can be only one level deeper than its parent. A file has one or more Screens at the top level.

Screen "Settings"Card "Profile"Input "Display name"

Labels, flags and props

A line starts with the Element type. After the type, write an optional Label, flags and props, in any order. The Label is a quoted string. Its meaning depends on the type. For example, it is the text of a Button, the value of a Stat and the alt text of an Image.

  • A flag is a lowercase word without a value. It means true. Examples are disabled, open and icon-only.
  • A prop has the form key=value. Put quotes around a value with spaces: placeholder="Jane Doe".
  • In a quoted value, \" is a quote and \\ is a backslash.
  • Only flags are bare words. Write variant=secondary. Do not write secondary alone.
  • A list prop has values separated by commas: options="Open,Paid". Write \, for a comma in a value.
Button "Save" variant=secondary icon=check disabled

Text lines, table rows and comments

A line with only a string is a paragraph. It is the same as a Text. A line that starts with | is a row of a Table or a Chart. Each row has one cell for each column. A line that starts with // is a comment. The Preview and the export ignore comments.

// A note for the human. Skizo does not show it."A paragraph of text."Table cols="Name,Role"| Ana Souza | Admin| Bruno Lima | Member

Slots

A slot word puts children into one part of their parent. Write the slot word on its own line. Then indent the children below it.

  • actions puts the children in the header of a Screen or a Card.
  • footer puts the children in the footer of a Card, a Dialog or a Sheet.
Card "Invoice"actionsButton "Download" icon=download icon-only variant=ghostText "Due on March 3"footerButton "Pay now"

Ids

All Elements accept id=name. An id is the target of opens= or to=. Each id must be unique in the file. If a Screen has no id, Skizo makes one from its Label. For example, Order details becomes order-details.

One content source

Give the content in one way only:

  • A Text has a Label or lorem=N.
  • A Table has | rows or rows=N.
  • A Chart has | rows or rows=N. It must have one of the two.
  • A List has items= or rows=N.

lorem=N and rows=N make placeholder content. The placeholder content is the same each time that you run Skizo.

Icons

The icon= prop takes the name of a Lucide icon in kebab case, for example plus, house or trash-2. If the name is not correct, skizo check shows the nearest name.

Behavior

Behavior is the effect of a click that you write in the source. Skizo has two kinds of Behavior:

  • opens=id on a Button shows the Dialog or Sheet with that id. The Dialog or Sheet must be on the same Screen.
  • to=screen-id on a Button or a Sidebar Link shows a different Screen of the file.

All other interactions work without Behavior:

  • A Tab shows its panel when you click it.
  • A Menu or a Select opens when you click it.
  • A Dialog or a Sheet closes from its close button, its backdrop or the Escape key. A footer Button without Behavior also closes it.

Form controls do not validate or send data.

Screen "Projects" id=projectsactionsButton "New project" icon=plus opens=new-projectButton "Open settings" variant=link to=settingsDialog "New project" id=new-projectInput "Name"footerButton "Create" Screen "Settings" id=settingsButton "Back to projects" variant=outline to=projects

The Preview shows one Screen at a time. The URL hash gives the name of the Screen. Thus the back button of the browser works. If the file has no to=, the Preview shows all Screens, one below the other.

Phones and tablets

Each sketch fits phones, tablets and desktops. Write one layout, and Skizo changes it for each width. On a phone (narrower than 768 px), a Grid shows one column. On a tablet (768 px to 1023 px), a Grid shows a maximum of two columns. A Row puts the children that do not fit on a new line. A Table scrolls horizontally. A Screen has less padding on a phone. On a phone, the Sidebar is hidden, and a button with the menu icon opens it from the left. The Preview and the export use the same Tailwind classes: md: for tablets and lg: for desktops.

The toolbar at the top of the Preview sets the width of the sketch: Desktop (1280 px), Tablet (768 px) or Phone (390 px). If the window is narrower than the width, the Preview makes the sketch smaller to fit the window. To open the Preview at a width, use --viewport:

skizo preview orders.skz --viewport phone

With --watch, the page keeps the width and the Screen after each reload.

  • 0 means that the command was successful.
  • 1 means that the file has errors.
  • 2 means that the command is not correct, or that Skizo cannot read the file.

shadcn export

skizo export --target shadcn writes React code. The code imports the components of your project from @/components/ui/*. Thus the export uses your theme and your changes to the components. Each Screen becomes one file with the name of its id. For example, orders.tsx exports OrdersScreen.

Requirements

  • A shadcn project on the Radix base. The export uses asChild.
  • The lucide-react package.
  • The shadcn components that the file uses: alert, avatar, badge, button, card, chart, checkbox, dialog, dropdown-menu, input, label, progress, radio-group, select, separator, sheet, switch, table, tabs and textarea.
  • The recharts package, if the file has a Chart. The shadcn chart component installs it.
  • For each Custom name, your component in @/components/<kebab-name>. For example, ChatBubble comes from @/components/chat-bubble.

Output

  • opens= becomes a useState hook. A click on the Button sets the state, and the state opens the Dialog or Sheet. The open flag sets the initial state to open.
  • to= becomes a plain <a href="/screen-id"> link. A Button with to= wraps the link with asChild.
  • --router next writes each link as <Link href="/screen-id"> and imports Link from next/link. A file with useState or a Chart starts with "use client". Then the App Router runs it in the browser.
  • --router react-router writes each link as <Link to="/screen-id"> and imports { Link } from react-router.
  • A shared Sidebar becomes one file, app-sidebar.tsx. It exports AppSidebar({ current }). Each Screen that shows the Sidebar renders <AppSidebar current="screen-id" />.
  • An export of an unchanged file writes the same bytes. Thus a diff shows only the changes that you made in the source.
